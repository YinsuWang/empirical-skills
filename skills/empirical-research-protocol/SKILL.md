# 通用实证研究框架

## 工作边界

负责决定本轮研究如何开展、执行什么分析、为何执行、如何判断证据及保存研究记录。将正式回归表、图形与论文式解读交给 `$empirical-results-reporting`；该 skill 不可用时，仍以清晰表格汇报实际结果。

保持主题、软件与识别方法通用。默认使用用户语言；用户使用 Stata 时优先衔接现有 do 文件，不为套用框架改换工具。

制度背景、识别来源的经济学判断及论文叙事主要由作者负责。沿用作者提供的政策事实、处理口径和设计，不将完整制度论证或背景图作为每轮分析的必交条件；只澄清会直接影响变量编码、估计对象或执行的必要信息。缺少背景论证时记入论文审查报告，不自动补写外生性故事或反复暂停分析。

## 启动本轮分析

1. 阅读当前数据、代码、研究说明与已有结果，确定已完成和待完成内容；避免重复询问可见信息。
2. 明确本轮是设计、执行、复现、诊断还是探索；限定本轮问题与产出。一次简单回归只执行必要步骤，不强行展开整篇论文。
3. 在内部 `analysis_plan.md` 中按已有信息记录问题、理论预测、Y、D/X、单位、目标参数、作者提供的识别设计、首选设定与推断。制度判断、待补论证及主要威胁转入独立审查报告；只在缺口直接妨碍正确执行时询问作者，继续不依赖该缺口的工作。
4. 读取 [研究阶段](references/research-stages.md)，选择适用步骤并标注：本轮执行、此前完成、待执行或不适用，以及理由。
5. 读取 [识别模块](references/identification-modules.md) 中相应方法，明确目标参数和诊断要求。遇到新方法、命令版本或不确定细节时核查论文、作者代码或官方软件文档；记录出处、包版本与选项，禁止猜命令。

## 正文与论文审查报告

读取 [输出边界](references/output-boundaries.md)。完整分析默认分别交付：

- `research_report.md`：可供论文正文使用的方法、数据定义、回归表和结果解释；沿用作者的叙事与章节安排。未指定的审查和检验内容不自动扩写成正文章节。
- `paper_review_report.md`：内部审查、数据/结果核验、诊断判定、尚存问题、证据充分性、下一步建议，以及论文证据安排表、外推边界和政策含义讨论。使用 [论文审查报告模板](assets/paper_review_report.md)。

正文不出现“已核验/待确认/仍需审查”等工作过程记录，也不自动插入“还不能据此得出结论”等防御性段落。作者指定入文的平行趋势、稳健性或其他实证分析，以其设计和实际结果表述；过程审查及对证据充分性的评价放在审查报告。准确报告参数、数值和统计证据，不通过分开报告将关联改写为已证实的因果效应。未执行/失败模型保存在内部记录和审查报告，不在正文机械罗列。

## 图形安排

DID相关研究在适用且数据支持时生成平行趋势/事件研究图；图的诊断评价放入审查报告，是否及如何入正文沿用任务约定。非DID研究的图形种类主要由作者决定，仅在作者明确指定或既有方案已要求时生成；不默认追加制度图、地图、散点图、RD图、forest plot或图形化识别证据。作者尚未决定的图形建议记录在审查报告，不作为继续回归的前提。

## 执行顺序

按适用范围推进：研究设计 → 数据审查 → 变量构造 → 描述事实 → 首选模型及基准比较 → 识别诊断 → 稳健性与证伪 → 合理的替代识别 → 机制及异质性 → 经济解释 → 复现审计。

在运行模型前按作者设计确定估计方法；研究执行顺序不等于正文目录。诊断失败时保留真实估计，把失败、解释限制和处理建议写入审查报告，正文按参数实际含义准确呈现结果。

内部分析遵循：**问题/威胁 → 设计与设定 → 估计或检验 → 结果 → 识别含义 → 下一步**。这条内部链不直接作为正文段落模板；正文围绕作者指定的研究问题、模型、结果及经济解释组织。

## 固定研究规则

- 区分关联、描述、预测与因果目标；不得因加入固定效应或控制变量就宣布因果识别。
- 根据作者已有依据注册首选模型，待补的理论/制度论证记入审查报告，不作为新增背景写作前置。保留探索过的主要模型，包括失败、不可估计、不显著和不支持假设的结果。
- 基准设定比较固定在同一共同样本内，仅比较是否加入登记的控制变量，以及无固定效应、仅时间固定效应、仅个体固定效应、个体与时间双向固定效应；具体组合及估计器适用性见研究阶段第4节。
- 核查共同支持、处理时间、样本选择、缺失、重复、异常值和数据合并；保护原始数据，禁止未经说明覆盖或删除。
- 控制变量和异质性分组优先使用处理前信息；明确处理后变量、碰撞变量及可能的内生控制。替换指标、缩尾和删除样本须说明依据并记录影响。
- 按处理赋值和误差依赖结构选择推断；报告聚类数量，遇少量聚类、序列/空间相关时选择适用修正，不机械地按数据行聚类。
- 不拒绝零假设不等于识别假设成立；显著性差异不等于组间效应差异；稳健性检验不自动修复原识别缺陷。
- 批量探索时列出有研究依据的设定范围，记录全部尝试及选择理由；同一数据上看结果后锁定设定不能自动成为独立验证。明确探索性质，必要时使用外部验证、留出样本或适当的多重检验/选择后推断。
- 替代估计器或识别策略可能估计不同参数、样本和权重，先核查可比性再讨论一致性。改变事件窗、样本或对照组时同步记录支持变化。
- 机制证据与因果中介效应分开。仅加入机制变量后系数下降不能证明中介机制。
- 不编造数据来源、结果、统计量、识别依据或已执行分析。不以“让平行趋势通过/让结果显著”为选择设定的理由。

## 记录与交接

保持现有项目结构；新项目默认建立 `analysis/` 下的 `code/`、`data-derived/`、`tables/`、`figures/`、`logs/`、`runs/<run-id>/`。将处理和模型代码纳入版本管理；受限原始数据只记录获取信息及校验值。

使用 [分析计划模板](assets/analysis_plan.md) 与 [模型注册表](assets/specification_registry.csv)。一行记录一个模型；多参数结果另用 tidy estimates 文件，关联同一 `spec_id`。

为每次执行保存运行 ID、数据版本/校验值、代码版本、软件及包版本、随机种子、命令、日志、样本筛选、成功/失败状态和结果路径。保留历史运行，避免覆盖丢失旧结果。

交给汇报 skill时分别标记“正文素材”和“论文审查素材”：前者含作者指定入文的方法、数据定义、表、已指定图及结果解读；后者含注册表/日志定位、数据与结果审查、诊断判定、待执行事项、证据安排、边界条件和政策讨论。对数字保留内部溯源，不把运行清单和审查意见混入正文。

## 完成前检查

核对实际命令已运行、数据与模型样本一致、输出能对应到 `spec_id`、诊断与因果措辞一致、未报告的探索结果已记录。将检查结果与下一步建议写入独立审查报告，优先处理尚未解决的识别威胁；正文不重复审查过程。
